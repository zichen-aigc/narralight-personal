## Agent 执行顺序

1. 检查系统和选定目录，确认 Git、Node 24、npm、Bun 1.3.14。缺失工具从官方或用户认可来源安装，优先用户目录；重开终端验证 PATH。本项目目前只在 Windows 验证；其他系统尝试核心工作台时如实标记兼容性。H3 DPAPI Worker 仅 Windows。
2. 新安装克隆上述公开仓库；已有目录核对 remote、分支和修改，勿 reset --hard。不要借用其他项目依赖来冒充新机安装。
3. 仓库根目录执行 `node scripts/setup.mjs`。默认不安装 H3、不下载模型。Bun 不在 PATH 时，用环境变量 `NARRALIGHT_BUN` 指定完整可执行路径。
4. 执行 `node start-personal.mjs`，保持终端开启，打开 http://127.0.0.1:3000 。需要后台持续运行时，使用可追踪 PID/日志的方式，记录停止方法，不保证临时工具会话永久存活。
5. 按下表验收。缺少供应商凭据不阻碍核心画布验收；生成能力单列未配置/未验。
6. 交付复用启动方式。若改了源码，列出文件和理由；自动更新要求工作区干净，不能丢弃修复或个人文件来满足条件。

## 遇到问题怎么补救

| 症状 | 排查与修复 |
| --- | --- |
| 找不到工具 | 检查版本、安装位置、PATH；重开终端或用完整路径，不反复重装全部软件 |
| 下载/证书/代理失败 | 定位失败的源，检查已有网络设置，合理重试并保存脱敏日志；不关闭 TLS 或随机换不可信镜像 |
| 锁文件/依赖失败 | 保留首个错误，核对 Node/Bun 版本，按锁文件重装当前目录依赖，不盲删锁文件或升级所有包 |
| Windows 文件锁/空格路径 | 查清占用当前目录的进程并正常关闭，正确引用路径，勿杀全部 Node/Python |
| 端口占用 | 核对监听进程所属项目；旧个人实例可正常停止，其他程序勿直接杀；改端口需同步代理与服务地址并复验 |
| 页面空白/插件缺失 | 看浏览器错误、构建和插件复制结果，检查实际插件 URL，不只看首页状态码 |
| 数据看起来丢失 | 检查 NARRALIGHT_PERSONAL_DATA_ROOT 和启动日志，备份后排查，不清空数据库试错 |
| H3 内存不足或不支持 | 跳过 H3，交付叙光核心；不以强行加载或交换文件保证可用 |

相同错误重复且没有新证据时换诊断路径，不无限重试。网络宕机、认证或硬件不足无法靠改源码保证解决，说明已完成部分、确切阻碍和最短补救动作。

安装记录写在仓库外的 `叙光安装记录.md`：日期、提交、系统/工具版本、安装/数据路径、启停命令、检查、脱敏错误与修复、未验功能、下一步。不保存密码、Token、私钥、业务数据。
